# AGENTS.md

> Структурная карта проекта для AI-агентов и новых участников.
> Обновляйте её при существенных изменениях структуры проекта.

## Обзор проекта

«Калька» — встраиваемый виджет, накладывающий слой правок поверх DOM прототипа:
заказчик правит тексты и оставляет аннотации прямо на странице. Тексты не меняются
в источнике — они подменяются при отображении.

**Главный потребитель экспортируемого файла — ИИ-агент**, который находит тексты
в исходниках прототипа и применяет замены. Продукт замыкает круг итерации:
прототип → правки в кальке → JSON → агент применяет → передеплой → тот же JSON
служит тестом того, что правки доехали.

## Технологический стек

- **Язык программирования:** TypeScript
- **UI-библиотека:** Preact (внутри Shadow DOM)
- **Сборка:** Vite, library mode → один IIFE-файл
- **Тесты:** Vitest
- **База данных:** нет — хранилище `localStorage`
- **ORM:** нет
- **Бэкенд:** нет, виджет полностью клиентский

## Структура проекта

Реализован этап 1 PRD «Каркас» (подключение, изоляция в Shadow DOM, три режима,
палитра) и веха «Слой и якоря» (FR-17, FR-19…FR-22): трёхуровневая привязка,
наложение после гидрации, переприменение при клиентской навигации и перерисовке,
сверка исходного текста, переключатель «оригинал / с правками».

## Правила для агентов

- Составные shell-команды разбивать на отдельные вызовы.
  - Неверно: `git checkout main && git pull`
  - Верно: сначала `git checkout main`, затем `git pull origin main`
- Базовая ветка проекта — `main`.
- Требования брать из `PRD — Калька.md`, ссылаясь на идентификаторы (FR-05, NFR-01).
  Не переизобретать требования, уже зафиксированные там.
- Формат обмена проектируется под ИИ-агента: поле оправдано настолько, насколько
  поднимает долю автоприменения (метрика M7). Читаемость человеком — вторая задача.
- В экспортируемый файл не попадает ничего, что агент мог бы принять за команду:
  ни путей к файлам, ни shell-команд, ни ссылок на инструкции (FR-46).
- Скилл `kalka-apply` (применение правок в исходниках) живёт **в репозитории прототипа**,
  а не здесь. Этап 6 по PRD.
- Архитектура — Feature-Sliced Design. Импорт только из слоёв строго ниже, слайсы одного
  слоя друг друга не импортируют, обращение к слайсу — только через его `index.ts`.
- Импорт между слоями и слайсами — по алиасам слоёв (`shared/lib/log`, `pages/review-mode`).
  Относительные пути допустимы только внутри своего слайса. Оба уровня проверяет
  `npm run lint`.
- Проверки бандла из `scripts/check-bundle.mjs` не ослабляются. Если появился `console`
  или внешний адрес — искать источник через `npx vite-bundle-visualizer`, а не смягчать
  проверку.
- В коде слово `widget` зарезервировано за слоем FSD. Продукт в коде — «Калька» / `kalka`.
- Виджет ничего не отправляет в сеть. Любой сетевой вызов в коде виджета — ошибка (NFR-03).
- Виджет не пишет в источник и не делает коммитов. В исходники пишет только агент,
  отдельно и по своему контракту.
