# Экспорт, импорт и версионирование

Реализация FR-27…FR-35. Обзор — в [../SKILL.md](../SKILL.md).

## Экспорт одного файла

FR-27 требует ОДИН файл выгрузки:

| Файл | Читатель | Роль |
|---|---|---|
| `kalka-<сайт>-<дата>.json` | ИИ-агент, затем виджет | правка исходников, потом импорт обратно на стенд |

Главный потребитель этого файла — **агент**, а не виджет: разработчик кладёт JSON
в репозиторий прототипа и запускает применение. Импорт в виджет — вторая роль того же
файла (разбор и проверка).

Второго файла выгрузки нет. Читаемая таблица Markdown, стоявшая здесь раньше, заменена
печатным ОТЧЁТОМ (`features/print-report`) — он не файл выгрузки, а документ, который
человек печатает в PDF средствами браузера. Отчёт умеет то, чего таблица не умела:
показывает картинку места каждой правки вырезкой вёрстки, несёт тот же сквозной номер,
что и метка на странице, и называет вид правки инструментом, которым она сделана.
Устроен он описью — одна таблица «№ · Место · Правка», без разделов по адресату, —
и называет свой файл обмена нейтральной строкой в шапке. Сценарий передачи стал таким:
рецензент отправляет разработчику файл обмена И напечатанный отчёт.

### Имя файла

FR-29: дата и адрес сайта.

```ts
function fileName(site: string, ext: string): string {
  const host = new URL(site).host.replace(/[:.]/g, '-')
  const date = new Date().toISOString().slice(0, 10)
  return `kalka-${host}-${date}.${ext}`
}
// kalka-devops-ap-corp-3711-2026-09-12.json
```

Двоеточие в имени файла недопустимо на Windows, точки путают расширение — заменяются оба.
Через неделю у разработчика в папке «Загрузки» лежит несколько таких файлов, и различать
их он будет именно по имени.

### Скачивание

```ts
function download(name: string, content: string, mime: string): void {
  const blob = new Blob([content], { type: `${mime};charset=utf-8` })
  const url = URL.createObjectURL(blob)
  const a = document.createElement('a')
  a.href = url
  a.download = name
  a.click()
  URL.revokeObjectURL(url)      // иначе blob висит в памяти до перезагрузки
}
```

`charset=utf-8` обязателен: без него кириллица в таблице откроется абракадаброй.

Два скачивания подряд некоторые браузеры считают подозрительными и блокируют второе.
Второй вызов ставится с небольшой задержкой:

```ts
download(fileName(site, 'json'), json, 'application/json')
setTimeout(() => download(fileName(site, 'md'), md, 'text/markdown'), 300)
```

### Предпросмотр перед экспортом

FR-28: рецензент видит список своих правок и может убедиться, что отправляет.

Это не диалог «уверены? да/нет» — такой диалог проматывают не читая. Это именно список
правок: последняя точка, где видно случайную правку или забытую пустую заготовку.

Флаг «не экспортировано» снимается **после** успешного скачивания, а не при открытии
предпросмотра.

## Импорт

### Разбор и проверка

```ts
function parse(raw: string): ExchangeFile {
  let data: unknown
  try {
    data = JSON.parse(raw)
  } catch {
    throw new ImportError('Не удалось прочитать файл — возможно, он повреждён')
  }

  if (!isObject(data) || (data as any).format !== 1) {
    throw new ImportError('Файл создан другой версией — правки не загружены')
  }

  const f = data as ExchangeFile
  if (!Array.isArray(f.entries)) {
    throw new ImportError('В файле нет правок')
  }

  return { ...f, entries: f.entries.filter(isValidEntry) }
}
```

Сообщения — по-русски и без технических терминов (FR-36). Слов «JSON», «формат 1»,
«парсинг» разработчик может и потерпеть, но тот же виджет открывает рецензент.

**Файл с неизвестной версией отклоняется целиком.** Частичное применение — тихая потеря
части правок, то есть нарушение Ц4. Лучше честное «не загружено», чем половина.

Отдельные битые записи внутри валидного файла отфильтровываются, но их количество
сообщается: «загружено 12 правок, 2 записи пропущены».

### Слияние

FR-33: несколько файлов складываются в один список с указанием автора.

```ts
function merge(current: StoredEntry[], incoming: ExchangeFile): StoredEntry[] {
  const stamped = incoming.entries.map((e) => ({
    ...e,
    author: incoming.author,
    importedAt: new Date().toISOString(),
  }))

  const seen = new Set(current.map((e) => `${e.author}:${e.id}`))
  const fresh = stamped.filter((e) => !seen.has(`${e.author}:${e.id}`))

  return [...current, ...fresh]
}
```

**Ключ дедупликации — `(author, id)`, не `id`.** `id` уникален только внутри одного файла;
два рецензента независимо сгенерируют одинаковые. Дедупликация по голому `id` молча
потеряла бы правку второго — снова нарушение Ц4.

**Слияние добавляет, не заменяет.** Разработчик грузит файл первого рецензента, затем
второго — и видит оба набора.

Повторная загрузка того же файла безопасна: все записи отсеются как виденные.
Об этом стоит сказать явно — «новых правок нет», иначе выглядит как будто импорт не сработал.

### Режим проверки после передеплоя

FR-35, новое в PRD 1.1. Тот же файл, которым правили, служит тестом того, что правки
доехали до исходников.

```ts
type VerifyStatus = 'arrived' | 'not-arrived' | 'unclear'

function verify(entry: TextOverride, root: Document): VerifyStatus {
  const wasFound = findText(entry.was, root)
  const nowFound = findText(stripTags(entry.now), root)

  if (!wasFound && nowFound) return 'arrived'      // зелёная
  if (wasFound) return 'not-arrived'               // красная
  return 'unclear'                                 // место изменилось иначе
}
```

Три исхода, а не два. `unclear` — когда на странице нет ни `was`, ни `now`: текст
поменяли, но не так, как просили, либо блок вообще убрали. Сводить этот случай
к `not-arrived` нельзя — он требует другого разбирательства.

Проверка выполняется только для `text-override`. Записи `style-wish` и `comment`
агент не применяет по определению, и «доехать» им некуда — они остаются задачами
человеку до явного закрытия.

Это прямая защита от риска R9 (тихая ошибка агента) и от нарушения метрики M8:
сверка занимает секунды и не требует ручного сравнения списков.

### Копирование текста

FR-34: текст правки копируется в буфер одной кнопкой.

```ts
async function copy(text: string): Promise<boolean> {
  try {
    await navigator.clipboard.writeText(text)
    return true
  } catch {
    return false     // нет разрешения или не HTTPS
  }
}
```

`navigator.clipboard` требует безопасного контекста. `http://example.internal:3711` из PRD
безопасным контекстом **не является** — а это ровно тот стенд, на котором всё и происходит.

Значит, запасной путь обязателен, а не желателен: если копирование не удалось, текст
показывается в поле, выделенным целиком, чтобы скопировать вручную. Кнопка, которая
молча не работает, хуже отсутствующей кнопки.

## Версионирование формата

`format: 1` — единственная защита от того, что новая версия виджета молча испортит
старый файл (NFR-08). Агент обязан отказываться от незнакомой версии так же, как виджет.

**Что можно без повышения версии:** добавить необязательное поле. Старый виджет его
проигнорирует, новый — использует.

**Что требует `format: 2`:**

- переименование или удаление поля;
- изменение типа поля;
- изменение смысла поля при том же имени и типе — самый опасный случай, потому что
  внешне файл остаётся валидным;
- изменение системы координат (доли ↔ пиксели).

При повышении версии старые файлы либо читаются миграцией, либо честно отклоняются.
Третьего — «попробуем прочитать и посмотрим» — быть не должно.

## Чек-лист

- [ ] Экспорт даёт ровно ОДИН файл обмена
- [ ] Читаемый вывод для человека даёт печатный отчёт, а не второй файл выгрузки
- [ ] Имя содержит дату и адрес, `:` и `.` в хосте заменены
- [ ] `charset=utf-8` в MIME-типе
- [ ] `URL.revokeObjectURL` вызван
- [ ] Набор помечается выгруженным по успеху этого одного файла
- [ ] Оформление показано словами, а не тегами
- [ ] Записи `lost` присутствуют в файле обмена
- [ ] Предпросмотр показывает список правок, а не диалог подтверждения
- [ ] Флаг «не экспортировано» снимается после скачивания
- [ ] Файл чужой версии отклоняется целиком
- [ ] Сообщения об ошибках без технических терминов
- [ ] Слияние добавляет, дедупликация по `(author, id)`
- [ ] У копирования в буфер есть запасной путь для не-HTTPS
