# Обнаружение уехавших якорей

Реализация FR-20, FR-31 и цели Ц4 («ни одна правка не теряется молча»).

## Зачем

Найти элемент мало. Селектор `main > section:nth-of-type(2) > h2` найдёт **какой-то**
заголовок и после того, как вёрстка переставит секции местами. Он найдёт не тот заголовок,
и правка «Тарифы на подключение» → «Специальные тарифы…» уедет на чужой блок.

Поэтому у каждой записи есть `was` — полный исходный текст на момент создания правки.
Он не помогает искать. Он помогает **не поверить** неверной находке.

## Три исхода наложения

```ts
type EntryStatus =
  | 'applied'   // нашли, текст сошёлся — правка наложена
  | 'drifted'   // нашли по фрагменту текста, либо текст сошёлся лишь частично
  | 'lost'      // не нашли ничего
```

Разделение на три состояния, а не на два, — принципиально. `drifted` означает
«вероятно, вот это место, проверь глазами», `lost` — «ищи руками, вот исходный текст».
Разработчику это разные задачи.

## Проверка

```ts
function matchesWas(el: Element, was: string): boolean {
  return normalize(el.textContent ?? '') === normalize(was)
}
```

Сравнение строгое, но **по нормализованному** тексту (`normalize` — та же функция, что
в [anchor-strategy.md](anchor-strategy.md)). Причина: вёрстка свободно меняет пробелы,
переносы строк и NBSP, не меняя смысла. Считать это расхождением — значит помечать
как уехавшие почти все правки после любой пересборки.

### Почему не «похожесть»

Соблазн — сравнивать с порогом (расстояние Левенштейна, доля общих слов) и считать
90% совпадения успехом. Не делаем: порог превращает бинарный, объяснимый ответ в
настраиваемое число, которое всегда либо слишком строгое, либо слишком мягкое,
и главное — **скрывает** от человека тот факт, что текст изменился.

Если текст изменился — это ровно тот случай, ради которого существует `drifted`.
Пусть человек решает.

## Наложение с определением статуса

```ts
interface Applied {
  entry: Entry
  status: EntryStatus
  element?: Element
  method?: AnchorMethod
}

function apply(entry: Entry, root: Document = document): Applied {
  const res = resolve(entry.anchor, entry.was, root)

  if ('status' in res) {
    return { entry, status: 'lost' }
  }

  return {
    entry,
    status: res.exact ? 'applied' : 'drifted',
    element: res.element,
    method: res.method,
  }
}
```

`resolve` уже вернул `exact: false` для находки по фрагменту текста — здесь это
транслируется в `drifted` без дополнительной логики.

## Что показывать человеку

Требование FR-36: рецензент не видит технических терминов. Требование FR-31: правки
с уехавшим якорем выделены явно, с текстом «было» для ручного поиска.

| Статус | Рецензенту (режим Правка) | Разработчику (режим Разбор) |
|---|---|---|
| `applied` | ничего особенного, правка видна на месте | обычная запись, клик прокручивает к месту |
| `drifted` | «страница изменилась — проверьте, что правка на месте» | запись с пометкой, клик прокручивает к предполагаемому месту, показан `was` |
| `lost` | «страница изменилась, это место больше не найдено» | запись без прокрутки, крупно показан `was` для поиска руками, текст правки копируется кнопкой |

Слов «якорь», «селектор», «XPath», «DOM» в интерфейсе нет ни в одном из состояний.
«Уехал якорь» — наш внутренний термин; пользователь читает «страница изменилась».

## Чего делать нельзя

**Нельзя молча пропускать `lost`.** Это прямое нарушение Ц4 и метрики M5 («правок,
потерянных молча: 0»). Запись со статусом `lost` обязана присутствовать в списке
и в экспорте наравне с остальными.

**Нельзя накладывать правку на элемент, не прошедший проверку, как `applied`.**
Лучше `drifted` с прокруткой к вероятному месту, чем уверенно наложенный чужой текст:
второе разработчик не заметит и применит.

## Пересчёт при переприменении

При SPA-навигации статусы пересчитываются заново для всех записей текущего маршрута.
Правка, бывшая `lost` на одном маршруте, может стать `applied` на другом — маршрут
входит в запись (`route`), и записи чужих маршрутов на текущей странице не накладываются
вовсе, а не помечаются как `lost`.

Различать эти два случая обязательно: «правка для другой страницы» и «правка, потерявшая
своё место» — разные вещи, и вторая требует внимания человека, а первая нет.
