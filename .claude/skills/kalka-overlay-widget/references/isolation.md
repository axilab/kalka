# Изоляция от сайта-носителя

Реализация FR-04 и NFR-06. Обзор — в [../SKILL.md](../SKILL.md).

Изоляция двусторонняя, и стороны решаются по-разному:

| Направление | Чем достигается | Насколько надёжно |
|---|---|---|
| Стили виджета → страница | Shadow DOM | Полностью |
| Стили страницы → виджет | Shadow DOM + `all: initial` | Только с явным сбросом |
| Разметка виджета → страница | Один host-элемент | Полностью |
| События виджета → страница | Ручная остановка | Требует внимания |
| Ошибки виджета → страница | `try/catch` на границах | Требует дисциплины |

## Стили виджета не текут наружу

Это Shadow DOM даёт бесплатно и полностью. Правила внутри shadow root к элементам
страницы не применяются вообще:

```js
const sheet = new CSSStyleSheet()
sheet.replaceSync('span { color: red }')
shadow.adoptedStyleSheets = [sheet]
// span-ы на странице не покраснели
```

## Стили страницы текут внутрь — и это надо чинить

Селекторы снаружи внутрь **не** проходят. А вот **наследование проходит**: `font-family`,
`font-size`, `color`, `line-height`, `letter-spacing`, `text-align`, `visibility`
наследуются в shadow root от хоста ровно так же, как в любой обычный элемент.

Считать, что Shadow DOM изолирует полностью, — самая частая ошибка при встраивании
виджетов. Реальность: `body { font-family: 'Comic Sans'; font-size: 11px }` испортит
интерфейс.

### Двойной сброс

Сбрасывать нужно **в двух местах**, и это не дублирование:

```ts
// 1. host — обычный элемент страницы, подчиняется её CSS
host.style.cssText = 'all: initial; position: fixed; z-index: 2147483647;'
```

```css
/* 2. :host — точка входа наследования в shadow tree */
:host {
  all: initial;
  font-family: system-ui, -apple-system, 'Segoe UI', Roboto, sans-serif;
  font-size: 14px;
  line-height: 1.4;
  color: #1a1a1a;
}
```

Первый защищает от правил вида `div { margin: 10px }` или `* { box-sizing: border-box }`,
которые применятся к host как к обычному `div`. Второй обрубает наследование внутрь.

После `all: initial` **всё** сброшено к initial-значениям, включая `box-sizing: content-box`
и `display: inline`. Поэтому сразу за сбросом задаются свои базовые значения — иначе
интерфейс поедет уже от собственных умолчаний.

### CSS custom properties сброс не берёт

`all: initial` **не сбрасывает** пользовательские свойства. Переменные носителя видны
внутри shadow root:

```css
/* на странице */
:root { --spacing: 40px }
/* внутри виджета — если использовать то же имя, получим 40px носителя */
```

Отсюда правило: все переменные виджета — с префиксом `--kalka-`. Коллизия
`--kalka-spacing` со страницей практически невозможна, `--spacing` — вопрос времени.

## Разметка: ровно один элемент

Виджет добавляет в `document.body` **один** элемент. Всё остальное — внутри shadow root
и в дереве страницы не видно.

```ts
const host = document.createElement('div')
host.setAttribute('data-kalka-root', '')
```

Атрибут `data-kalka-root` — то, по чему собственные узлы отличаются от чужих при обходе
DOM. На него ссылается `WIDGET_ROOT_SELECTOR` в [kalka-anchoring](../../kalka-anchoring/SKILL.md):
без него обход текстовых узлов зайдёт внутрь собственного интерфейса.

### z-index

`2147483647` — максимальное 32-битное знаковое целое, потолок `z-index`. Перебить его
нельзя, но это **не гарантия**: `z-index` работает внутри контекста наложения. Если
носитель создал контекст наложения на предке (`transform`, `filter`, `opacity < 1`,
`will-change`, `contain: paint`), виджет окажется заперт внутри него.

Защита — вешать host **прямо на `document.body`**, а не внутрь произвольного контейнера.
`position: fixed` вдобавок сам создаёт контекст наложения относительно вьюпорта, если
на предках нет `transform`.

## События через границу

По MDN событие с `composed: true` пересекает границу shadow root, но его `target`
для слушателей снаружи **ретаргетится** на host-элемент. Внутренняя структура наружу
не протекает.

Композитными являются `click`, `focus`, `input`, `change` — то есть почти всё, чем
пользуется интерфейс. Некомпозитными — `reset`, `invalid`, `load`.

Практическое следствие: **клик по кнопке виджета всплывает до `document`** и может
сработать на обработчике носителя (закрыть модалку, свернуть меню, перейти по ссылке).

```ts
// Внутри виджета, на корне интерфейса
root.addEventListener('click', (e) => e.stopPropagation())
```

`stopPropagation`, но **не** `preventDefault`: отменять действие по умолчанию для
собственных элементов не нужно, а привычка ставить оба ломает фокус и ввод с клавиатуры.

### Как отличить свой клик от чужого

Виджету это нужно постоянно: в режиме правки клик по странице выбирает элемент, а клик
по палитре инструментов — нет.

```ts
function isOurs(e: Event): boolean {
  return e.composedPath().some(
    (n) => n instanceof Element && n.hasAttribute?.('data-kalka-root')
  )
}
```

**Проверять `e.target` бесполезно** — из-за ретаргетинга снаружи он равен host-элементу
для любого клика внутри виджета, и различить внутренние элементы по нему невозможно.
`composedPath()` отдаёт полный путь, включая узлы внутри открытого shadow root.

Альтернатива для быстрой проверки: `target.getRootNode() !== document` — узел живёт
в shadow tree, а не в основном документе.

## Глобальное состояние

Виджет делит с носителем `window`, `document`, `history`, `localStorage`.

- **`localStorage`**: все ключи с префиксом `kalka:`. Хранилище общее с сайтом — ключ
  `entries` затрёт чужие данные или будет затёрт.
- **`history`**: патч `pushState`/`replaceState` обязан сохранять и вызывать оригинал.
  Правила безопасного патча — в [kalka-anchoring/references/reapply.md](../../kalka-anchoring/references/reapply.md).
- **`window`**: одно свойство `window.__kalka` для защиты от повторной загрузки.
  Больше в глобальную область не пишем.

```ts
if ((window as any).__kalka) return   // скрипт подключён дважды
;(window as any).__kalka = { version: __VERSION__, unmount }
```

Двойное подключение — реальный сценарий: разработчик добавил скрипт в шаблон,
а рецензент открыл ссылку с `?kalka`, и сборщик вставил его ещё раз.

## Полный демонтаж

Виджет обязан уметь исчезнуть, вернув страницу в исходное состояние:

```ts
function unmount(): void {
  stopLayer()        // снять правки, вернуть исходные тексты
  stopNavigation()   // вернуть history.pushState / replaceState
  stopMutations()    // observer.disconnect()
  stopLayout()       // снять слушатели scroll / ResizeObserver
  render(null, mountPoint)
  host.remove()
  delete (window as any).__kalka
}
```

Нужен не только ради чистоты: без него нельзя честно проверить, что виджет не оставляет
следов, а это и есть проверка NFR-06.
