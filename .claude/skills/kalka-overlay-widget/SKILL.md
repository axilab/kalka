# Виджет «Калька» как гость на чужой странице

Виджет подключается одной строкой `<script>` к прототипу, который мы не контролируем
и не меняем (FR-01). Отсюда весь набор ограничений: **виджет — гость. Он не имеет права
ломать хозяина, даже ломаясь сам.**

Три требования PRD, из которых следует всё остальное:

- **FR-04** — интерфейс изолирован Shadow DOM: его стили не текут в сайт, стили сайта не ломают его.
- **NFR-06** — виджет не ломает вёрстку и работу носителя; при ошибке внутри виджета сайт продолжает работать.
- **NFR-01** — бандл ≤ 100 КБ gzip.

## Главное заблуждение про Shadow DOM

Shadow DOM изолирует стили **не полностью**. Правило-селектор снаружи внутрь не проходит:
`span { color: blue }` на странице не покрасит `<span>` внутри shadow root. Но
**наследуемые свойства проходят через границу по наследованию**: `font-family`, `color`,
`font-size`, `line-height` спускаются в shadow root от хоста, как в любой обычный элемент.

Практически: сайт с `body { font-family: 'Ужасный Шрифт'; font-size: 11px }` испортит
интерфейс виджета, несмотря на Shadow DOM. Это ровно тот сценарий, который запрещает FR-04.

Лечится сбросом на хосте:

```css
:host {
  all: initial;        /* обрубает наследование от страницы */
  /* дальше — свои значения с нуля */
  font-family: system-ui, -apple-system, 'Segoe UI', Roboto, sans-serif;
  font-size: 14px;
  line-height: 1.4;
  color: #1a1a1a;
}
```

`all: initial` сбрасывает наследуемые свойства **и не трогает CSS custom properties** —
переменные страницы всё равно видны внутри. Если носитель определил `--color` и виджет
случайно использует то же имя, они столкнутся. Поэтому все свои переменные — с префиксом
(`--kalka-*`).

Подробности изоляции, включая события и `z-index`, — в [references/isolation.md](references/isolation.md).

## Точка входа и guard активации

FR-03: виджет **не активируется**, если не включён явно. Забытый скрипт не должен уехать
в прод рабочим.

```ts
const FLAG = 'kalka'

function shouldActivate(): boolean {
  const params = new URLSearchParams(location.search)
  if (params.has(FLAG)) return true
  try {
    return localStorage.getItem('kalka:enabled') === '1'
  } catch {
    return false   // приватный режим, отключённые куки — не падаем
  }
}
```

Активация через `?kalka` **и** через флаг в `localStorage`: параметр включает виджет
в первый раз, флаг переживает переход по внутренним ссылкам без параметра. Без второго
рецензент потеряет виджет на первом же клике по меню.

Любой доступ к `localStorage` — в `try/catch`: в приватном режиме и при отключённом
хранилище обращение бросает исключение, а не возвращает `null`.

## Отказоустойчивость

NFR-06 — не пожелание, а требование. Виджет живёт в чужом окружении, где что угодно
может оказаться не таким, как ожидалось.

```ts
function boot(): void {
  if (!shouldActivate()) return

  try {
    mountWidget()
  } catch (e) {
    // Сайт продолжает работать. Наружу — ничего (NFR-03).
    if (import.meta.env.DEV) console.error('[kalka]', e)
  }
}
```

Три правила:

1. **Каждая граница обёрнута.** Загрузка, обработчики событий, колбэки наблюдателей,
   патчи чужих методов — всё, откуда исключение может уйти в код носителя.
2. **Ошибка не уходит в сеть.** Ни телеметрии, ни отчётов (NFR-03). `console.error` —
   только под `import.meta.env.DEV`, из продакшен-сборки вырезается.
3. **Виджет умеет полностью убраться.** Снять слой, отписаться от событий, вернуть
   пропатченные методы, удалить host-элемент.

## Монтирование Preact в shadow root

```ts
function mountWidget(): () => void {
  const host = document.createElement('div')
  host.setAttribute('data-kalka-root', '')
  host.style.cssText = 'all: initial; position: fixed; z-index: 2147483647;'
  document.body.appendChild(host)

  const shadow = host.attachShadow({ mode: 'open' })

  const sheet = new CSSStyleSheet()
  sheet.replaceSync(styles)          // styles — строка, см. сборку
  shadow.adoptedStyleSheets = [sheet]

  const mount = document.createElement('div')
  shadow.appendChild(mount)
  render(<App />, mount)

  return () => {
    render(null, mount)
    host.remove()
  }
}
```

**`mode: 'open'`, не `'closed'`.** Closed не даёт безопасности (обойти его тривиально),
зато ломает отладку и мешает нашему же коду отличить свои узлы от чужих при обходе DOM.

**Инлайновый `all: initial` на самом host-элементе** нужен потому, что host — обычный
элемент страницы и подчиняется её CSS. Без него правило носителя вида `div { margin: 10px }`
сдвинет весь виджет.

**`adoptedStyleSheets`, а не `<style>`.** Браузер парсит таблицу один раз, и она
не участвует в дереве — меньше работы при перерисовке.

## Сборка: один файл, одна строка

PRD требует подключение одной строкой `<script>` без сборки на стороне сайта (FR-01).
Значит: формат `iife`, всё внутри, включая CSS.

```ts
// vite.config.ts
export default defineConfig({
  plugins: [preact()],
  build: {
    lib: {
      entry: 'src/index.ts',
      name: 'Kalka',            // обязателен для iife/umd
      formats: ['iife'],
      fileName: () => 'kalka.js',
    },
    cssCodeSplit: false,
    target: 'es2020',
  },
})
```

CSS **не должен** выезжать отдельным файлом: это была бы вторая строка подключения.
Импортируется строкой и уходит в `adoptedStyleSheets`:

```ts
import styles from './widget.css?inline'
```

`?inline` — механизм Vite: содержимое CSS приходит строкой в JS вместо отдельного ресурса.

Контроль бюджета обязателен в сборке, а не на глаз:

```bash
gzip -c dist/kalka.js | wc -c    # < 102400
```

Подробности конфига, внешние зависимости и разбор размера — в
[references/build.md](references/build.md).

## Бюджет 100 КБ gzip

Preact — причина выбора (NFR-02): он и заметно меньше React, и не конфликтует с React
носителя, если тот есть.

Правила расходования бюджета:

- Любая новая зависимость обосновывается размером. Редактор форматированного текста —
  единственное место, где внешняя библиотека вероятно оправдана; всё остальное
  (якоря, хранилище, экспорт) делается платформенными API.
- Никаких иконочных шрифтов и картинок — инлайновые SVG.
- Никакой загрузки шрифтов с CDN: это и вес, и нарушение NFR-03/NFR-04
  (виджет обязан работать за VPN и на `localhost` без внешних сервисов).
- Полифилы не тянем: целевые браузеры по NFR-05 — актуальные, `es2020` они держат.

## Что виджет не имеет права делать

- **Писать в файлы сайта или делать коммиты** — прямая не-цель PRD.
- **Ходить в сеть.** Ни телеметрии, ни ошибок, ни шрифтов, ни аналитики (NFR-03).
- **Ломать вёрстку носителя.** Только `position: fixed`-слой поверх; layout страницы
  не трогается.
- **Оставаться активным без явного флага** (FR-03).
- **Молча глотать ошибки применения правок.** Ошибка виджета не должна ломать сайт —
  но потерянная правка обязана быть видна (Ц4).
