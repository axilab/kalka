# Калька

Слой правок поверх прототипа. Заказчик правит тексты и оставляет аннотации прямо
на странице, а разработчик получает правки в применимом виде.

Ключевой принцип: **тексты не меняются в источнике — они подменяются при отображении.**
Виджет накладывает слой поверх DOM, сайт-носитель о нём не знает и не меняется.

Полные требования — в [`PRD — Калька.md`](PRD%20—%20Калька.md).

## Состояние

Круг правок работает целиком: заказчик размечает живую страницу, выгружает два
файла, разработчик разбирает их в списке и проверяет, что правки доехали.

- подключение одной строкой `<script>` и включение по явному признаку;
- изоляция интерфейса в Shadow DOM: стили носителя внутрь не проходят,
  стили виджета наружу не текут;
- три инструмента: правка текста с форматированием, обведённая область
  и указатель с замечанием;
- трёхуровневая привязка к месту (CSS-селектор → XPath → фрагмент текста)
  с явной пометкой уехавших мест;
- хранение в браузере, переживающее перезагрузку, и выгрузка двумя файлами:
  машинным и читаемым;
- накопительная загрузка чужих файлов, список с группировкой по страницам
  и переходом к месту, режим проверки после передеплоя;
- поля для ИИ-агента: тип записи, маршрут, исходный текст с разметкой,
  контекст до и после, число вхождений строки на странице.

Чего ещё **нет**: скилла `kalka-apply`, применяющего правки в исходниках.
Это следующая веха, а не пропуск.

## Интерфейс

Рейка шириной 48px у правого края видна всегда: три инструмента, переключатель
вида страницы и вход в разбор. Прототип остаётся виден
и прокручиваем — виджет занимает полосу у края, а не ложится поверх страницы.

- **Инструменты** — сегментированный переключатель: выбран ровно один, повторное
  нажатие выключает. У каждой иконки всплывает подпись по наведению и по фокусу
  с клавиатуры, а у выбранного инструмента появляется подсказка, чем он
  выключается. На кнопке стоит число правок, сделанных ЭТИМ инструментом;
  при нуле значка нет.
- **Вид страницы** — одна кнопка на три состояния: с правками → где изменения →
  оригинал и снова с правками. Подпись и рисунок называют то, что на экране
  сейчас.
- **Окно правки и окно замечания** встают выноской у того места, о котором
  говорят: у правимой строки, у поставленной метки. Не помещается снизу —
  переворачиваются вверх, у края экрана прижимаются внутрь.
- **Разбор** выезжает ящиком ~360px во всю высоту от рейки. Ящик собран
  каркасом: шапка с именем, список правок между чертами, полоса загрузки
  и проверки под ним и подвал с «Экспортом» и «Отчётом». «Экспорт» залит,
  пока набор не выгружен, и становится обычным после. Правки идут
  первыми — инструменты разработчика стоят под ними, а не занимают первый
  экран. «Экспорт» в подвале скачивает файл сразу — выбирать в выгрузке
  нечего, уходит всегда весь набор. Закрытый ящик выпадает из обхода
  с клавиатуры, но не размонтируется: режим проверки и отчёт о загрузке
  переживают закрытие.
- **Запись списка** набрана как правка на полях: номер в своей колонке слева,
  текст во второй, соседей разделяет волосок. У записи под курсором и под
  фокусом появляется плашка действий у правого края: удалить правку и
  скопировать её текст. Высоту строки плашка не меняет — она стоит поверх.
- **Удаление отменяемо.** Правка снимается сразу — страница возвращает
  исходный текст, метка исчезает, номера сдвигаются, — но на её месте
  в списке пять секунд стоит полоса с кнопкой «Вернуть», и отмена ставит
  запись ровно туда, где она была. У чужой правки полоса говорит прямо:
  у автора в файле она осталась.
- **Метки на странице** — корректорские: уголки у обведённой области, выноска
  на поле у указателя, подчёркивание под правкой текста. У каждой метки номер,
  и он же стоит в строке списка — по нему место находится в обе стороны.
- На экране уже 640px рейка становится полосой внизу, а ящик занимает всю ширину.

Насыщенный цвет в интерфейсе один и появляется только на том, что нанёс
человек. Сам инструмент себя цветом не выделяет: его роль — лист кальки поверх
чужого чертежа.

## Подключение

Одна строка в разметке страницы:

```html
<script src="https://axilab.github.io/kalka/kalka.js"></script>
```

По этому адресу лежит последняя сборка из `main`: конвейер обновляет его
на каждый push. Версия не закрепляется — прототип, подключённый сегодня,
завтра получит новую сборку. Свой файл подключается так же, локальным
путём вида `/kalka.js`.

Виджет молчит, пока его не включили явно, — забытый скрипт не уезжает в прод рабочим:

| Адрес | Что происходит |
|---|---|
| `?kalka` | включает и запоминает: виджет переживёт переход по внутренним ссылкам |
| `?kalka=0`, `?kalka=off`, `?kalka=false` | выключает и забывает |
| без параметра | решает запомненный признак |

В хранилище сайта виджет держит **один** ключ — `kalka:enabled` со значением `1`.
Больше он туда ничего не пишет, а `?kalka=0` этот ключ удаляет.

Управлять виджетом из консоли можно через `window.__kalka`: `unmount()` возвращает
страницу в исходное состояние целиком, включая само свойство `window.__kalka`.

## Разработка

```
npm install
npm run dev
```

Дев-сервер отдаёт страницы-мишени — намеренно недружелюбные страницы, на которых
проверяется то, чего не видно в тестах:

| Страница | Что проверяет |
|---|---|
| `dev/index.html` | контрольная: здесь виджет обязан выглядеть эталонно |
| `dev/hostile-css.html` | агрессивный CSS носителя: чужой шрифт, цвет, рамки, `!important`-правила |
| `dev/stacking.html` | контекст наложения на предке и блок носителя у правого края — приёмочный случай для рейки |
| `dev/spa.html` | клиентская навигация: виджет не мешает ей и не исчезает |
| `dev/text.html` | инструмент «Текст»: подсветка, окно правки выноской, форматирование, вставка из Word |
| `dev/marks.html` | метки области и указателя: рисование, замечание, геометрия в долях |
| `dev/layer.html` | наложение слоя и якоря: уехавшие места, подсветка цели, переприменение |
| `dev/storage.html` | хранение в браузере и выгрузка файла обмена |
| `dev/review.html` | загрузка правок, список с группировкой и режим проверки после передеплоя |
| `dev/report.html` | отчёт о правках и печать: четыре случая вырезки, включая заведомо непригодный |
| `dev/agent.html` | поля для ИИ-агента: контекст записи, маршрут, число вхождений |
| `dev/built.html` | собранный файл, подключённый одной строкой (нужен `npm run build`) |

Открывать с параметром: `http://localhost:5173/dev/index.html?kalka`.

Остальные команды:

```
npm test
npm run typecheck
npm run lint
npm run build
```

## Сборка и ограничения

`npm run build` собирает один самодостаточный файл `dist/kalka.js` и сразу проверяет
его пятью проверками (`scripts/check-bundle.mjs`):

1. в `dist/` ровно один файл — подключение одной строкой;
2. размер не больше 100 КБ gzip, и цифра печатается на каждой сборке;
3. ни одного внешнего адреса — виджет ничего не грузит извне;
4. нет `react-dom` — он не должен просочиться транзитивной зависимостью;
5. нет ни одного вызова `console` — в продакшен-сборке виджет молчит.

Любая непройденная проверка роняет сборку с кодом возврата 1.

**Занято на 2026-09-06:** 41 104 байта gzip из 102 400 — это 40.1 КБ в единицах
самой проверки, свободно 59.9 КБ. Веха «Отчёт о правках» добавила 7 409 байт
(7.2 КБ gzip) при собственном потолке в 15 КБ — замер переснят после того,
как отчёт научился доснимать место правки прямо в момент печати.

Методика замера названа здесь, потому что прежний замер её не назвал и разошёлся
с нынешним без объяснимой причины: `npm run build`, затем `gzipSync` над
`dist/kalka.js` целиком, стандартный уровень сжатия Node. `check-bundle.mjs`
делит полученные байты на 1024 — отсюда «КБ» в его выводе.

**Проверки не ослабляются.** Если в бандле появился `console` или внешний адрес,
источник ищется через `npx vite-bundle-visualizer`, а не смягчением регулярного
выражения.

Единственное исключение — пространства имён `http://www.w3.org/…` из ядра Preact.
Это аргументы `createElementNS`, то есть строковые идентификаторы, по которым браузер
никуда не ходит; без исключения падала бы каждая сборка. Список исключений пополняется
только такими же строками и только с объяснением, почему сетевого обращения не будет.

## Структура

Архитектура — Feature-Sliced Design. Модуль импортирует только из слоёв строго ниже,
слайсы одного слоя друг друга не импортируют, обращение к слайсу — только через его
`index.ts`.

| Слой | Роль |
|---|---|
| `app` | инициализация: признак активации, монтирование в Shadow DOM, движок наложения, рейка и ящик |
| `pages` | содержимое ящика разбора |
| `widgets` | самодостаточные блоки интерфейса: палитра, редактор, слой меток, список правок, выгрузка |
| `features` | действия пользователя: правка текста, область, указатель, экспорт, загрузка, проверка |
| `entities` | понятия предметной области: правка, привязка, контекст для агента |
| `shared` | переиспользуемое без привязки к домену: UI-кит, внешние границы, утилиты, типы |

Подробные правила — в [`.ai-factory/ARCHITECTURE.md`](.ai-factory/ARCHITECTURE.md).

**Направление зависимостей проверяет линтер, а не договорённость.** `npm run lint`
контролирует оба уровня: `no-restricted-imports` — импорты по алиасам слоёв,
локальное правило `kalka/relative-inside-boundary` — относительные пути.
Соглашение: между слоями и слайсами импорт идёт по алиасам (`shared/lib/log`,
`pages/review-mode`), относительные пути допустимы только внутри своего слайса.

## Приватность

Наружу не уходит ничего: ни телеметрии, ни отчётов об ошибках, ни содержимого правок.
Виджет не загружает шрифты и стили со сторонних адресов — всё, что ему нужно, лежит
в бандле. Запрет закрыт с двух сторон: линтер ловит намерение в исходниках
(`fetch`, `XMLHttpRequest`, `WebSocket`, `EventSource`, `sendBeacon`), проверка бандла —
факт в артефакте.
