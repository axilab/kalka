# Калька

«Калька» — встраиваемый слой согласования правок поверх работающего сайта или
прототипа. Заказчик видит страницу в браузере, меняет тексты прямо в контексте,
обводит проблемные области и оставляет замечания. Разработчик получает не набор
скриншотов и сообщений, а структурированный файл с точным местом каждой правки.

Сам виджет **не изменяет исходный код сайта**. Он временно накладывает изменения
поверх DOM, чтобы заказчик сразу видел желаемый результат. После согласования
правки экспортируются и переносятся в исходники разработчиком или ИИ-агентом.

## Какую проблему решает

Обычно согласование сайта выглядит так:

1. заказчик делает скриншот;
2. пишет «здесь заменить текст» или «передвинуть этот блок»;
3. разработчик пытается понять, о какой странице и элементе идёт речь;
4. вручную перепечатывает текст и ищет его в исходниках;
5. после обновления стороны ещё раз сверяют, все ли замечания учтены.

«Калька» переносит этот разговор на сам сайт:

1. разработчик подключает виджет и отправляет заказчику ссылку;
2. заказчик правит текст и оставляет пометки непосредственно на странице;
3. виджет сохраняет исходный и новый текст, маршрут, DOM-якорь и окружающий
   контекст;
4. заказчик экспортирует один JSON-файл и при необходимости печатный отчёт;
5. разработчик или ИИ-агент применяет изменения к исходникам;
6. после передеплоя тот же JSON можно импортировать и проверить, какие текстовые
   правки действительно появились на сайте.

Главная идея: **правка должна содержать достаточно контекста, чтобы её можно
было понять и применить без переписки «что именно вы имели в виду».**

## Что умеет виджет

- редактировать видимый текст с базовым форматированием;
- отдельно фиксировать пожелания к размеру и цвету текста;
- обводить область страницы и прикреплять к ней комментарий;
- ставить точечный указатель с комментарием;
- показывать оригинал, страницу с правками и места изменений;
- хранить незавершённую работу в браузере;
- экспортировать правки в машиночитаемый JSON;
- формировать печатный отчёт с изображением места каждой правки;
- импортировать несколько файлов от разных рецензентов;
- восстанавливать пометки на странице после импорта;
- после передеплоя показывать, какие текстовые правки доехали, не доехали или
  требуют ручной проверки.

Для привязки к месту используется каскад:

```text
CSS-селектор → XPath → фрагмент текста
```

Прямоугольники и указатели хранят координаты относительно элемента-якоря,
поэтому меньше зависят от разрешения экрана и изменений размеров страницы.

## Что получает разработчик или ИИ-агент

Экспортируемый JSON — одновременно файл передачи, сохранения и последующей
проверки. Для каждой записи он содержит, среди прочего:

- тип изменения: замена текста, пожелание по оформлению или комментарий;
- маршрут страницы;
- исходный текст и исходную HTML-разметку;
- новый текст;
- ближайший заголовок;
- текст до и после изменённого элемента;
- человекочитаемый путь к месту;
- количество повторов исходной строки на странице;
- DOM-якорь и размер окна на момент создания правки.

Файл специально разделяет данные, которые можно применять механически, и
замечания, требующие решения человека. Если место в исходниках нельзя определить
однозначно, агент не должен угадывать.

> В репозитории пока нет готового скилла `kalka-apply`, автоматически
> применяющего JSON к исходникам конкретного проекта. Сейчас файл можно передать
> разработчику или coding-агенту как структурированное техническое задание.

## Подключение к сайту

Добавьте одну строку в HTML, желательно перед закрывающим `</body>`:

```html
<script src="https://axilab.github.io/kalka/kalka.js"></script>
```

По этому адресу публикуется последняя сборка из ветки `main`. Если для проекта
важна воспроизводимость, скачайте `kalka.js`, положите рядом с сайтом и подключите
собственную копию:

```html
<script src="/tools/kalka.js"></script>
```

Подключённый скрипт по умолчанию ничего не показывает. Виджет активируется только
по явному признаку.

### Включение и выключение

| Адрес | Результат |
|---|---|
| `https://example.com/page?kalka` | Включить виджет и запомнить выбор для этого сайта |
| `https://example.com/page?kalka=0` | Выключить виджет и удалить сохранённый признак |
| `?kalka=off` или `?kalka=false` | То же, что `?kalka=0` |
| Адрес без параметра | Использовать сохранённое состояние |

После первого открытия с `?kalka` виджет сохраняет в `localStorage` сайта:

```text
kalka:enabled = 1
```

Поэтому при переходах внутри SPA параметр можно не добавлять к каждой ссылке.

## Запуск на любом сайте через DevTools

«Кальку» можно временно запустить на странице, не меняя её HTML, репозиторий или
production-сборку. Для этого достаточно выполнить готовый `kalka.js` в консоли
браузера.

Этот способ полезен, когда:

- нет доступа к исходникам сайта;
- нельзя быстро пересобрать прототип;
- нужно разово собрать замечания на уже опубликованной странице;
- сайт работает во внутренней сети и внешнее подключение скрипта запрещено.

### Шаг 1. Скопируйте код виджета

Откройте в отдельной вкладке:

<https://axilab.github.io/kalka/kalka.js>

Выделите всё содержимое страницы и скопируйте его. Это собранный исполняемый
файл, а не исходный TypeScript из каталога `src`.

### Шаг 2. Откройте консоль нужного сайта

Откройте страницу, на которой нужно оставить правки, затем инструменты
разработчика:

- Chrome/Edge на macOS: `⌥ Option` + `⌘ Command` + `J`;
- Chrome/Edge на Windows/Linux: `Ctrl` + `Shift` + `J`;
- либо меню браузера → «Инструменты разработчика» → `Console`.

Убедитесь, что консоль открыта в контексте основной страницы, а не вложенного
`iframe`.

### Шаг 3. Разрешите показ виджета

Выполните в консоли:

```js
localStorage.setItem('kalka:enabled', '1')
```

Флаг нужно установить **до** выполнения `kalka.js`: при запуске виджет сначала
проверяет разрешение на активацию и без него завершает работу.

### Шаг 4. Выполните `kalka.js`

Вставьте в консоль всё содержимое скопированного файла и нажмите `Enter`.
У правого края страницы должна появиться панель «Кальки».

Некоторые браузеры защищают консоль от случайной вставки кода и показывают
предупреждение Self-XSS. Следуйте подсказке самого браузера только если вы
самостоятельно открыли указанный выше файл и доверяете его содержимому. Никогда
не вставляйте в DevTools код, присланный неизвестным человеком.

### Важное ограничение консольного запуска

Флаг в `localStorage` сохраняется, но вставленный JavaScript действует только в
текущем документе:

- при переходах внутри SPA виджет продолжит работать;
- после полной перезагрузки страницы или перехода с загрузкой нового HTML код
  исчезнет, и `kalka.js` потребуется вставить снова;
- созданные правки останутся в `localStorage` этого origin и появятся после
  повторного запуска виджета.

`localStorage` привязан к origin. Правки и флаг, созданные на
`https://example.com`, не будут доступны на `http://example.com`, другом порту
или поддомене.

### Удаление временно запущенного виджета

Чтобы снять слой со страницы и вернуть оригинальное отображение:

```js
window.__kalka?.unmount()
```

Чтобы одновременно запретить автоматическую активацию при следующем запуске:

```js
window.__kalka?.unmount()
localStorage.removeItem('kalka:enabled')
```

Удаление флага не удаляет сохранённые правки. Не очищайте данные сайта до
экспорта: записи хранятся локально в браузере и могут быть потеряны.

## Приватность

Виджет не отправляет данные наружу:

- нет телеметрии;
- нет аналитики;
- нет API и удалённой базы данных;
- нет загрузки внешних шрифтов или стилей;
- тексты и комментарии остаются в браузере до ручного экспорта.

Production-сборка автоматически проверяется на отсутствие внешних адресов,
`react-dom` и обращений к `console`. Сетевые API дополнительно запрещены
линтером в исходниках.

Если используется публичный адрес GitHub Pages, браузер один раз загружает с него
сам файл `kalka.js`. Для закрытого контура скачайте файл и раздавайте его со
своего сервера либо вставляйте готовую сборку через DevTools.

## Ограничения

- Виджет работает с содержимым, представленным обычным HTML DOM. Текст внутри
  `canvas`, изображения или закрытого cross-origin `iframe` недоступен.
- Данные находятся в `localStorage` конкретного браузера и origin, пока
  рецензент не экспортировал файл.
- Полная перезагрузка страницы удаляет код, вставленный через DevTools.
- Автоматический поиск исходника сложнее для строк, собранных во время выполнения:
  i18n-шаблонов, интерполяций и данных из CMS.
- Виджет не изменяет файлы проекта и не делает коммиты.

## Разработка

Требуется Node.js и npm.

```bash
npm install
npm run dev
```

Контрольная страница:

```text
http://localhost:5173/dev/index.html?kalka
```

Проверки проекта:

```bash
npm test
npm run typecheck
npm run lint
npm run build
```

`npm run build` создаёт один файл `dist/kalka.js` и проверяет, что:

1. в `dist` нет дополнительных файлов;
2. размер не превышает 100 КБ gzip;
3. в бандле нет внешних адресов;
4. в бандл не попал `react-dom`;
5. production-код не обращается к `console`.

Архитектура проекта построена по Feature-Sliced Design. Полное описание
требований находится в [`PRD — Калька.md`](PRD%20—%20Калька.md), структурная
карта для разработчиков и агентов — в [`AGENTS.md`](AGENTS.md).
