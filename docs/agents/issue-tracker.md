# Трекер задач: локальный markdown

Задачи и спецификации этого репозитория живут markdown-файлами в `.scratch/`.

## Соглашения

- Одна фича — одна папка: `.scratch/<фича-слаг>/`
- Спецификация — `.scratch/<фича-слаг>/spec.md`
- Задачи на реализацию — по файлу на тикет: `.scratch/<фича-слаг>/issues/<NN>-<слаг>.md`,
  нумерация с `01`, никогда не один общий файл со всеми тикетами
- Состояние триажа — строкой `Status:` вверху файла задачи
  (строки ролей см. в `triage-labels.md`)
- Комментарии и история обсуждения дописываются в конец файла под заголовком `## Comments`

## Когда скилл говорит «опубликовать в трекер»

Создать новый файл в `.scratch/<фича-слаг>/`, при необходимости создав папку.

## Когда скилл говорит «взять нужный тикет»

Прочитать файл по указанному пути. Обычно пользователь передаёт путь или номер задачи напрямую.

## Операции wayfinder

Используются скиллом `/wayfinder`. **Карта** — файл, у которого по файлу на каждый дочерний тикет.

- **Карта**: `.scratch/<работа>/map.md` (тело: Notes / Decisions-so-far / Fog).
- **Дочерний тикет**: `.scratch/<работа>/issues/NN-<слаг>.md`, нумерация с `01`, вопрос в теле.
  Строка `Type:` — тип тикета (`research`/`prototype`/`grilling`/`task`),
  строка `Status:` — `claimed`/`resolved`.
- **Блокировки**: строка `Blocked by: NN, NN` вверху файла. Тикет разблокирован,
  когда все перечисленные файлы в состоянии `resolved`.
- **Фронтир**: просмотреть `.scratch/<работа>/issues/` и отобрать открытые, незаблокированные
  и никем не взятые; побеждает первый по номеру.
- **Взять в работу**: поставить `Status: claimed` и сохранить до начала работы.
- **Закрыть**: дописать ответ под заголовком `## Answer`, поставить `Status: resolved`,
  затем добавить указатель на контекст в раздел Decisions-so-far в `map.md`.
