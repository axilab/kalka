# Публикация «Кальки» на GitHub

Дата: 2026-09-06. Статус: согласовано, готово к плану реализации.

## Задача

Репозиторий становится публичным opensource-проектом на GitHub. Главная цель —
общедоступный адрес собранного файла: строка `<script src="…">`, которую можно
вставить в любой прототип и получить рабочий виджет. Всё остальное (лицензия,
документация, оформление репозитория) обслуживает эту цель.

Сейчас: git-remote нет вообще, `package.json` помечен `private: true`, `dist/`
в `.gitignore`, ветка по умолчанию `master`, 64 коммита, все ветки `feature/*`
влиты в `master` и ничего не добавляют.

## Принятые решения

| Вопрос | Решение |
|---|---|
| Способ раздачи | GitHub Pages |
| Владелец и имя | `axilab/kalka` |
| Схема адресов | только latest, без папок версий |
| Состав публикации | всё как есть, включая PRD, `AGENTS.md`, `.ai-factory`, `.claude`, `.codex` |
| Лицензия | MIT, `Copyright (c) 2026 axilab` |
| История | целиком, отправляется только `master` → `main` |
| Триггер публикации | каждый push в `main` |
| Содержимое сайта | файл сборки плюс краткая инструкция, без демо |
| Язык документации | русский, как сейчас |
| Оформление | минимум: LICENSE, README, описание, топики; Issues включены |
| Ветка по умолчанию | переименовать `master` → `main` до первого push |
| Создание репозитория | через `gh`, ставится из brew |

## Адреса

- `https://axilab.github.io/kalka/kalka.js` — сборка, всегда последняя из `main`.
- `https://axilab.github.io/kalka/` — страница с адресом и строкой подключения.

Закрепления версии нет: прототип, подключённый сегодня, завтра молча получит
новую сборку. Это прямое следствие решения «только latest». Папки вида
`/v0.1.0/kalka.js` можно добавить позже, не ломая существующий адрес.

## Конвейер

Один файл `.github/workflows/pages.yml`, два job.

**`check`** — на `push` в `main` и на `pull_request`:
`npm ci` → `npm run lint` → `npm run typecheck` → `npm test` → `npm run build`.
Проверка бюджета бандла уже входит в `npm run build` (скрипт вызывает
`check:bundle`), отдельный шаг не нужен.

**`deploy`** — только на `push` в `main`, `needs: check`. Собирает каталог сайта
и выкладывает официальной парой `actions/upload-pages-artifact` +
`actions/deploy-pages`. Права job: `pages: write`, `id-token: write`. Группа
`concurrency` — `pages`, чтобы параллельные выкатки не наступали друг на друга.

Источник Pages в настройках репозитория ставится в режим «GitHub Actions».
Ветка `gh-pages` не заводится, `dist/` остаётся в `.gitignore` — собранный файл
никогда не попадает в историю.

### Ограничение, определяющее устройство сборки сайта

`scripts/check-bundle.mjs` требует, чтобы в `dist/` лежал **ровно один** файл
`kalka.js`, иначе сборка падает (это проверка FR-01: подключение одной строкой).
Поэтому `index.html` в `dist/` не кладётся. Job `deploy` собирает отдельный
каталог `site/`:

1. `npm run build` — даёт `dist/kalka.js`;
2. `mkdir -p site`;
3. копия `dist/kalka.js` в `site/kalka.js`;
4. копия шаблона `scripts/site/index.html` в `site/index.html`;
5. `site/` уходит в артефакт Pages.

`site/` добавляется в `.gitignore`.

## Изменения в файлах

**Новые:**

- `LICENSE` — текст MIT, `Copyright (c) 2026 axilab`.
- `.github/workflows/pages.yml` — конвейер, описанный выше.
- `scripts/site/index.html` — шаблон страницы сайта: русский текст, публичный
  адрес файла, строка подключения одной строкой, таблица признака активации
  (`?kalka`, `?kalka=0`), ссылки на репозиторий и лицензию. Оформление —
  минимальное и самодостаточное, без внешних загрузок.

**Правятся:**

- `README.md` — из перечня «чего ещё нет» уходит «единого адреса для подключения
  бандла»: он появляется. В разделе «Подключение» вместо `/kalka.js` встаёт
  публичный адрес, рядом — абзац о том, что адрес отражает `main` и версия не
  закрепляется.
- `package.json` — добавляются `license: "MIT"`, `repository`, `homepage`,
  `keywords`; `description` уже есть. Поле `private: true` **остаётся**: пакет
  в npm не публикуется, а флаг защищает от случайной публикации.
- `.gitignore` — добавляется `site/`.

Ничего вычищать из репозитория не требуется: `.claude/settings.local.json`
и `.playwright-mcp/` не отслеживаются git, секретов в истории нет (совпадения
в скане нашлись только в примерах внутри документации по безопасности).

## Порядок выкатки

1. `brew install gh`.
2. Пользователь один раз выполняет `gh auth login` сам — ввод интерактивный.
3. `git branch -m master main`.
4. Коммит подготовительных изменений.
5. `gh repo create axilab/kalka --public --source=. --remote=origin --push`
   с описанием; отправляется только `main`.
6. Топики репозитория через `gh repo edit --add-topic`: `widget`, `preact`,
   `shadow-dom`, `prototyping`, `overlay`, `typescript`.
7. Включение Pages в режиме Actions (`build_type: workflow`).
8. Ожидание первого прогона конвейера.

## Проверка результата

Задача считается закрытой не по зелёному значку workflow, а по трём фактам:

1. `curl -sI https://axilab.github.io/kalka/kalka.js` отдаёт 200 и тип
   JavaScript;
2. размер выложенного файла совпадает с локальной сборкой;
3. страница-мишень из `dev/`, переписанная на публичный адрес, поднимает виджет
   по `?kalka`.

Пока это не показано, работа не завершена.

## Что осознанно не делается

- Публикация в npm — способ раздачи выбран другой.
- Папки версий на Pages и закрепление версии — прямо отклонено решением
  «только latest».
- `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, шаблоны issue и PR — оформление
  минимальное, обещаний поддержки не даётся.
- Перевод документации на английский.
- Демо-страница с живым виджетом на Pages.
