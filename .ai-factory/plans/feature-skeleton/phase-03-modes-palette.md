# Фаза 3: Три режима и палитра инструментов

План: [index.md](index.md)
Задачи: 13–16
Зависит от: фазы 2 (задачи 9, 10, 11)

## Цель

FR-02 целиком: за раз показан ровно один режим — Просмотр, Правка или Разбор,
переходы между ними доступны в одно нажатие. В режиме Правка есть палитра из трёх
инструментов с сохраняющимся выбором. Весь текст — по-русски, без технических
терминов (FR-36).

Границы этапа: инструменты **выбираются, но ничего не делают со страницей** —
подсветка элемента, редактор текста, рисование области и постановка метки
относятся к этапу 3 PRD (FR-05…FR-16). Режим Разбор показывает пустое состояние:
импортировать пока нечего, импорт — этап 4 PRD (FR-30…FR-35).

## Task 13: Палитра инструментов

### Назначение

Палитра — то, ради чего рецензент открывает режим Правка. В этапе 1 она отвечает
за одно: показать три инструмента и запомнить выбранный. Поведение инструментов
подключается в этапе 3 PRD к уже существующим кнопкам, без переделки разметки.

### Шаги реализации

1. Дополнить `src/shared/model/ui.ts`:

```ts
/** Режим виджета. За раз показан ровно один (FR-02). */
export type Mode = 'view' | 'edit' | 'review'

/** Инструмент палитры (FR-05…FR-14). Поведение подключается на этапе 3 PRD. */
export type Tool = 'text' | 'area' | 'point'
```

2. Создать `src/widgets/tool-palette/ui/ToolPalette.tsx`:

```tsx
import type { JSX } from 'preact'
import type { Tool } from 'shared/model/ui'
import { Button } from 'shared/ui/Button'

/**
 * Подписи инструментов. Порядок массива задаёт порядок кнопок и меняется
 * только вместе с PRD: рецензент привыкает к расположению.
 */
const TOOLS: ReadonlyArray<{ readonly id: Tool; readonly label: string }> = [
  { id: 'text', label: 'Текст' },
  { id: 'area', label: 'Область' },
  { id: 'point', label: 'Указатель' },
]

export interface ToolPaletteProps {
  selected: Tool | null
  onSelect: (tool: Tool) => void
}

export function ToolPalette({ selected, onSelect }: ToolPaletteProps): JSX.Element {
  const chosen = TOOLS.find((tool) => tool.id === selected)

  return (
    <div>
      <div class="kalka-row">
        {TOOLS.map((tool) => (
          <Button
            key={tool.id}
            selected={tool.id === selected}
            onClick={() => onSelect(tool.id)}
          >
            {tool.label}
          </Button>
        ))}
      </div>
      <p class="kalka-note">
        {chosen ? `Выбрано: ${chosen.label}` : 'Выберите инструмент'}
      </p>
    </div>
  )
}
```

3. Создать `src/widgets/tool-palette/index.ts`:

```ts
export { ToolPalette } from './ui/ToolPalette'
export type { ToolPaletteProps } from './ui/ToolPalette'
```

4. Кнопки **не** помечаются отключёнными. На этапе 3 PRD к ним добавляется поведение,
   и разметка при этом не меняется; отключённая кнопка потребовала бы обратной правки.
   Обратная связь на нажатие есть уже сейчас: выделение кнопки и строка «Выбрано: …».

### Требуемые интерфейсы и контракты

- Публичный API слайса — `ToolPalette` и `ToolPaletteProps`.
- Компонент **не хранит состояние**: выбранный инструмент приходит пропсом и меняется
  через `onSelect`. Хранение — в `app/ui/Root.tsx` (задача 16), чтобы выбор пережил
  переход в Разбор и обратно.
- `Tool` — ровно три значения. Добавление четвёртого инструмента требует правки PRD.
- Палитра не импортирует `pages` и другие слайсы `widgets` (проверяется линтером).

### Обработка ошибок и логирование

Компонент представления, границ с чужим кодом нет — логирования нет. Событие смены
инструмента логирует `Root` (задача 16): там же, где живёт состояние.

### Тесты

Файл `src/widgets/tool-palette/ui/ToolPalette.test.tsx`,
запуск: `npx vitest run src/widgets/tool-palette`.

1. Отрисовка при `selected={null}` даёт ровно три кнопки с текстами
   «Текст», «Область», «Указатель» в этом порядке и строку «Выберите инструмент».
2. При `selected="area"` строка равна «Выбрано: Область», и класс
   `kalka-button--selected` стоит ровно на одной кнопке — второй.
3. Нажатие на кнопку «Указатель» вызывает `onSelect` один раз с аргументом `'point'`.

Оснастка та же, что в фазе 2: `render` из `preact` в контейнер в `document.body`.

### Критерии приёмки

- Три теста проходят.
- Ни одна кнопка не имеет атрибута `disabled`.
- Порядок кнопок совпадает с порядком в PRD: Текст, Область, Указатель.

## Task 14: Режим Правка

### Назначение

Второй из трёх режимов FR-02: развёрнутая панель с палитрой и переходами
в остальные режимы.

### Шаги реализации

1. Создать `src/pages/edit-mode/ui/EditMode.tsx`:

```tsx
import type { JSX } from 'preact'
import type { Tool } from 'shared/model/ui'
import { ToolPalette } from 'widgets/tool-palette'
import { Button } from 'shared/ui/Button'

export interface EditModeProps {
  selectedTool: Tool | null
  onSelectTool: (tool: Tool) => void
  /** Свернуть виджет в кнопку. */
  onCollapse: () => void
  /** Перейти к списку правок. */
  onReview: () => void
}

export function EditMode({
  selectedTool,
  onSelectTool,
  onCollapse,
  onReview,
}: EditModeProps): JSX.Element {
  return (
    <div class="kalka-panel">
      <p class="kalka-title">Правка</p>
      <ToolPalette selected={selectedTool} onSelect={onSelectTool} />
      <div class="kalka-row">
        <Button onClick={onReview}>Разбор</Button>
        <Button onClick={onCollapse}>Свернуть</Button>
      </div>
    </div>
  )
}
```

## Task 16: Переключение режимов в Root

### Назначение

Собрать три режима в один корневой компонент так, чтобы за раз был показан ровно один
(FR-02), а выбранный инструмент переживал уход в Разбор и обратно.

### Шаги реализации

1. Заменить `src/app/ui/Root.tsx`:

```tsx
import type { JSX } from 'preact'
import { useState } from 'preact/hooks'
import { EditMode } from 'pages/edit-mode'
import { ReviewMode } from 'pages/review-mode'
import { ViewMode } from 'pages/view-mode'
import type { Mode, Tool } from 'shared/model/ui'
import { createLogger } from 'shared/lib/log'

const log = createLogger('root')

export function Root(): JSX.Element {
  const [mode, setMode] = useState<Mode>('view')
  const [tool, setTool] = useState<Tool | null>(null)

  function go(next: Mode): void {
    log.debug('смена режима', { было: mode, стало: next })
    setMode(next)
  }

  function choose(next: Tool): void {
    log.debug('выбран инструмент', { инструмент: next })
    setTool(next)
  }

  if (mode === 'edit') {
    return (
      <EditMode
        selectedTool={tool}
        onSelectTool={choose}
        onReview={() => go('review')}
        onCollapse={() => go('view')}
      />
    )
  }

  if (mode === 'review') {
    return <ReviewMode onEdit={() => go('edit')} onCollapse={() => go('view')} />
  }

  return <ViewMode onOpen={() => go('edit')} />
}
```

2. Ветка `view` возвращается последней и без условия: так исключается состояние,
   в котором не отрисовано ничего. Тип `Mode` из трёх значений при этом остаётся
   исчерпанным.
3. Состояние держится хуками Preact, а не сигналами: в этапе 1 состояний два,
   потребитель у них один, и `@preact/signals` был бы зависимостью без работы.
   Сигналы вводятся вместе с хранилищем правок (этап 4 PRD), где подписчиков
   действительно несколько.

### Требуемые интерфейсы и контракты

- `Root` не принимает пропсов: его монтирует `app/lib/mount.ts` через `h(Root, {})`.
- Начальный режим — `view`. Виджет никогда не открывается развёрнутым:
  страница прототипа должна оставаться страницей прототипа.
- Выбранный инструмент хранится в `Root`, а не в `EditMode`: иначе он терялся бы
  при уходе в Разбор.
- Переходы: Просмотр → Правка; Правка → Разбор, Правка → Просмотр;
  Разбор → Правка, Разбор → Просмотр. Прямого перехода Просмотр → Разбор нет —
  он не нужен, пока разбирать нечего.

### Обработка ошибок и логирование

- `debug` на каждую смену режима с прежним и новым значением, `debug` на выбор
  инструмента. Настройка плана — подробное логирование; переходы между режимами
  и есть основной наблюдаемый ход работы виджета.
- Границ с чужим кодом у компонента нет: клики уже остановлены на корне интерфейса
  (`app/lib/mount.ts`), обёртка `safely` здесь не нужна.

### Тесты

запуск: `npx vitest run src/app/ui/Root.test.tsx`.

## Риски фазы и меры

- **Риск:** асинхронная перерисовка Preact делает тесты переходов «мигающими».
  **Мера:** после каждого нажатия ожидается микрозадача (`await Promise.resolve()`).
  Это записано в оснастке задачи 16; `setTimeout` в тестах не используется.
- **Риск:** выбранный инструмент теряется при смене режима, и на этапе 3 PRD это
  вскроется как «инструмент сбрасывается сам».
  **Мера:** состояние поднято в `Root`, тест 3 задачи 16 проверяет именно это.
- **Риск:** в интерфейс просачиваются технические термины.
  **Мера:** тест 7 задачи 16 механически ищет запрещённые слова во всех трёх режимах,
  тест 4 задачи 15 дублирует проверку для Разбора на уровне слайса. На дев-стенде
  в фазе 4 текст остаётся под наблюдением, но уже не как единственная защита.
