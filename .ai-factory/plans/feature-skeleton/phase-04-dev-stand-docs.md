## Task 17: Дев-стенд из пяти страниц-мишеней

### Назначение

Три вещи из чек-листа изоляции не проверяются в jsdom в принципе: наследование
шрифта и цвета через границу shadow root, контекст наложения на предке и работа
собранного IIFE-файла. Для них нужны настоящие страницы в настоящем браузере.

### Шаги реализации

1. Создать `dev/index.html` — обычная статическая страница с заголовками, абзацами,
   списком и карточками. Подключение виджета:

```html
<script type="module" src="/src/app/index.ts"></script>
```

   Никаких стилей, кроме минимальных: это контрольная мишень, на которой виджет
   обязан выглядеть правильно.

2. Создать `dev/spa.html` — та же разметка плюс маленький роутер на ванильном JS:
   три ссылки, обработчик кликов вызывает `history.pushState`, подменяет содержимое
   `<main>` и обрабатывает `popstate`. Ни фреймворка, ни сборки: страница проверяет
   поведение виджета при клиентской навигации, а не чужой роутер.
   В этапе 1 виджет на навигацию не реагирует — страница нужна, чтобы убедиться,
   что он **не мешает** ей и не исчезает; переприменение слоя появится на этапе 2 PRD.

3. Создать `dev/hostile-css.html` — та же разметка плюс агрессивные правила носителя
   в `<style>`:

```css
* { box-sizing: content-box !important; }
body { font-family: 'Comic Sans MS', cursive; font-size: 11px; color: #b30000; }
div {
  margin: 10px !important;
  padding: 4px !important;
  border: 1px dashed #b30000 !important;
  position: static !important;
  right: auto !important;
  bottom: auto !important;
  z-index: -1 !important;
}
button { font-size: 9px; background: #ffd400; border-radius: 0; }
:root { --spacing: 40px; --color: #b30000; }
```

   Это прямая проверка FR-04: интерфейс виджета обязан остаться неизменным.
   Переменные `--spacing` и `--color` объявлены нарочно — они показывают, почему
   собственные переменные носят префикс `--kalka-`. Правила для `div` намеренно
   используют `!important`: обычный inline-стиль host проиграл бы им, поэтому задача 11
   задаёт критические свойства через `style.setProperty(..., 'important')`.

4. Создать `dev/stacking.html` — разметка обёрнута в контейнер, создающий контекст
   наложения:

```html
<div style="transform: translateZ(0); position: relative; z-index: 0"> … </div>
```

   Плюс перекрывающий блок с `position: fixed; z-index: 999999`. Виджет обязан
   остаться поверх: его host висит прямо на `document.body`, а не внутри контейнера.

5. Создать `dev/built.html` — единственная страница, подключающая **собранный** файл:

```html
<script src="../dist/kalka.js"></script>
```

   Ею проверяется FR-01 буквально: одна строка, никакого `type="module"`, никакого
   отдельного CSS-файла.

6. Все пять страниц открываются с параметром `?kalka`. На `dev/index.html`
   дополнительно проверяется, что **без** параметра и при пустом хранилище виджет
   не появляется вовсе.

7. Дев-страницы не попадают в бандл: `build.lib.entry` указывает только на
   `src/app/index.ts`. Убедиться, что после `npm run build` в `dist/` по-прежнему
   один файл.

### Требуемые интерфейсы и контракты

- Страницы обслуживаются дев-сервером Vite: `npm run dev`, адреса вида
  `http://localhost:5173/dev/index.html?kalka`.
- `dev/built.html` требует предварительного `npm run build`. Если дев-сервер
  не отдаёт `../dist/kalka.js` как статический файл, страница открывается напрямую
  из файловой системы (`file://`) — бандл является классическим скриптом и этого
  достаточно. Под `file://` доступ к `localStorage` может быть запрещён браузером;
  это ожидаемо и обрабатывается `try/catch` в `shared/api/storage`, а активация
  в этом случае работает только через `?kalka`.
- Дев-страницы — инструментарий, а не код виджета: они в `ignores` конфига ESLint
  (фаза 1, задача 5) и вне `tsconfig.json`.
- Разметка страниц пишется по-русски и напоминает страницу прототипа: заголовки,
  абзацы, карточки. Тексты-заглушки вида «Lorem ipsum» не использовать — на них
  не видно проблем с кириллицей и переносами.

### Обработка ошибок и логирование

Собственного кода виджета страницы не содержат. На дев-сервере
`import.meta.env.DEV === true`, поэтому в консоли браузера виден весь подробный
вывод логгера — это и есть способ наблюдать ход работы виджета на стенде.

### Тесты

Модульных тестов у дев-страниц нет: их назначение — ручная проверка того, что
в jsdom не воспроизводится. Проверочный список приведён в разделе «Проверка»
и повторён в чек-листе завершения фазы.

### Критерии приёмки

- Пять страниц открываются и содержат осмысленное русское содержимое.
- На `dev/index.html` без `?kalka` и при пустом хранилище виджета нет вовсе;
  с `?kalka` появляется кнопка «Калька».
- На `dev/hostile-css.html` интерфейс виджета выглядит так же, как на `dev/index.html`:
  системный шрифт, свой размер, свои цвета, свои рамки.
- На `dev/hostile-css.html` вычисленные стили host сохраняют `position: fixed`,
  `right: 16px`, `bottom: 16px`, `z-index: 2147483647`, несмотря на конфликтующие
  `!important`-правила носителя.
- На `dev/stacking.html` виджет виден поверх перекрывающего блока.
- На `dev/spa.html` переходы по ссылкам не ломают виджет и не приводят к ошибкам
  в консоли.
- На `dev/built.html` виджет работает при подключении одной строкой `<script>`.
- В консоли браузера нет ошибок, не относящихся к виджету намеренно.
- `window.__kalka.unmount()` в консоли убирает виджет, и `document.body` не содержит
  элементов с `data-kalka-root`.
- На `dev/built.html` без `?kalka` в `window` нет ни одного имени, содержащего `kalka`:
  ни `__kalka`, ни `Kalka`.

### Проверка

- `npm run dev`, открыть `http://localhost:5173/dev/index.html`
  Ожидаемо: страница обычная, виджета нет.
- Открыть `http://localhost:5173/dev/index.html?kalka`
  Ожидаемо: в правом нижнем углу кнопка «Калька»; в консоли строки `[kalka:boot]`
  и `[kalka:mount]`.
- Перейти на `http://localhost:5173/dev/index.html` (без параметра)
  Ожидаемо: виджет на месте — сработал запомненный флаг.
- Открыть `http://localhost:5173/dev/index.html?kalka=0`
  Ожидаемо: виджета нет, и на последующих переходах без параметра его тоже нет.
- Открыть `http://localhost:5173/dev/hostile-css.html?kalka`, сравнить внешний вид
  панели с контрольной страницей
  Ожидаемо: отличий нет.
- На той же странице выполнить в консоли:
  `getComputedStyle(document.querySelector('[data-kalka-root]'))`
  Ожидаемо: `position === 'fixed'`, `right === '16px'`, `bottom === '16px'`,
  `zIndex === '2147483647'`; правило `div { ... !important }` host не перебило.
- Открыть `http://localhost:5173/dev/stacking.html?kalka`
  Ожидаемо: панель поверх перекрывающего блока.
- Открыть `http://localhost:5173/dev/spa.html?kalka`, пройти по всем ссылкам и нажать
  «назад»
  Ожидаемо: виджет остаётся на месте, ошибок в консоли нет.
- `npm run build`, затем открыть `dev/built.html?kalka`
  Ожидаемо: виджет работает; в консоли **пусто** — логгер вырезан из продакшен-сборки.
- В консоли выполнить `window.__kalka.unmount()`
  Ожидаемо: виджет исчез, `document.querySelectorAll('[data-kalka-root]').length === 0`.
- Открыть `dev/built.html` **без** `?kalka` при очищенном хранилище и выполнить в консоли
  `Object.keys(window).filter((k) => /kalka/i.test(k))`
  Ожидаемо: пустой массив. Это механическая проверка Definition of Done «виджет не пишет
  в `window`»: `name: 'Kalka'` в конфиге сборки глобальной переменной не заводит, пока
  точка входа ничего не экспортирует (задача 12, шаг 4). Непустой результат означает,
  что в `src/app/index.ts` появился экспорт, — искать его, а не смягчать требование.

## Task 18: README и обновление структурной карты

### Назначение

NFR-07: код пишется как потенциально открываемый — без секретов, с README и внятной
структурой. `AGENTS.md` сейчас утверждает, что `src/` не создан, а README отсутствует;
после этого плана оба утверждения ложны, а устаревшая карта хуже отсутствующей.

Настройка плана — обязательный чекпоинт документации, поэтому правки документации
проводятся через `/aif-docs`, а не пишутся мимо него.

### Шаги реализации

1. Создать `README.md` со следующими разделами:
   - **Что это** — две-три фразы: слой правок поверх прототипа, тексты не меняются
     в источнике, подменяются при отображении. Ссылка на `PRD — Калька.md`.
   - **Состояние** — реализован этап 1 PRD «Каркас»: подключение, изоляция, три режима,
     палитра. Инструменты пока не действуют на страницу, обмен файлами не реализован.
   - **Подключение** — одна строка `<script src="/kalka.js"></script>` и включение
     параметром `?kalka`; выключение и забывание — `?kalka=0`. Явно сказать, что
     виджет хранит один ключ `kalka:enabled` в `localStorage` сайта и больше ничего.
   - **Разработка** — `npm install`, `npm run dev`, адреса дев-страниц и назначение
     каждой.
   - **Сборка и ограничения** — `npm run build`; перечислить пять проверок
     `scripts/check-bundle.mjs` (один файл в `dist/`, бюджет 100 КБ gzip, отсутствие
     внешних адресов, отсутствие `react-dom`, отсутствие `console.`) и правило:
     **проверки не ослабляются**. Если появился `console` или внешний адрес, источник
     ищется через `npx vite-bundle-visualizer`. Отдельно объяснить единственное
     исключение — пространства имён `http://www.w3.org/…` из ядра Preact: это
     аргументы `createElementNS`, а не загрузка ресурса, и список исключений
     пополняется только такими строками, с объяснением.
   - **Структура** — шесть слоёв FSD одной таблицей, ссылка на
     `.ai-factory/ARCHITECTURE.md`. Отдельной строкой: импорт между слоями

   - **Приватность** — виджет не отправляет наружу ничего; сетевые вызовы запрещены

   - **Каталог `spike/`** — одноразовый код гейтов R1 и R8, вне FSD и вне бандла,

   - раздел «Структура проекта»: заменить абзац «Кода виджета ещё нет: `src/` не создан»

## Риски фазы и меры

- **Риск:** дев-сервер Vite не отдаёт `dist/kalka.js`, и `dev/built.html` не работает.
  **Мера:** страница открывается напрямую из файловой системы; ограничение
  `localStorage` под `file://` описано в контракте задачи 17 и уже обработано
  в коде хранилища.
- **Риск:** ручная проверка изоляции проводится небрежно и пропускает расхождение.
  **Мера:** сравнение ведётся с контрольной страницей `dev/index.html`, а не «на глаз
  по памяти»; список пунктов приведён в разделе «Проверка» задачи 17.
- **Риск:** README устареет на следующем же этапе.
  **Мера:** раздел «Состояние» описывает границу этапа явно, поэтому расхождение
  будет заметно сразу, а не накопится.
